# App evaluation context

Fill this file from actual project configuration and verified device observations. Unknown values remain unknown; examples are not evidence. Keep this shared file free of credentials, personal data and references to private runs or captures.

## Project setup

Record the applicable build variant, application ID, backend/environment, locale, login/session prerequisites and diagnostic capabilities. Cite the project's own source/configuration for source-derived facts. Do not infer the backend from a build-type name alone.

## Private local context

Optional `docs/agent-eval/APP_CONTEXT.local.md` holds authorized test-account aliases, credentials and developer-specific settings. Ignore it in Git, preserve existing entries and restrict permissions to its owner. Prefer existing sessions. Do not copy its values into task prompts, shared notes or run reports. Stop on unexpected authentication challenges.

## Feature index

Add links to relevant files under `flows/` after real observations exist. Each note records its own date, source/build/environment, provenance, validation status and revalidation conditions. No run-specific facts have been recorded in this template.

## Evidence boundaries

Shared context and feature notes must work across sessions without local artifacts. Private history belongs in ignored `docs/agent-eval/runs/`; raw captures belong in ignored `.agent-eval/artifacts/`. Load only knowledge relevant to the current feature.
